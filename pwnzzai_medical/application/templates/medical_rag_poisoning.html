RAG Poisoning

Description

RAG poisoning and model poisoning are related AI security vulnerabilities that target the data influencing a model’s behavior. In Retrieval-Augmented Generation (RAG), external repository data is retrieved at runtime and added to prompts to provide context through in-context learning. Because this augmentation data can contain sensitive or business-critical information, manipulating it can cause the model to generate misleading, unsafe, or malicious outputs without changing the model itself. This is known as RAG poisoning or augmentation data manipulation. Model poisoning, in contrast, occurs when malicious or corrupted data is introduced during training or continuous runtime learning, altering the model’s internal behavior, potentially creating biased responses or hidden backdoors. Since RAG repositories effectively influence model behavior in a similar way to training data, they require comparable security protections and integrity controls.

Demonstration

At MediCare AI, emergency situations require fast protocol lookups 🏥🚑. Doctors and nurses rely on the internal Clinical Protocol Assistant to handle critical situations. It answers practical questions like:

  • What is the immediate protocol for a patient with severe tachycardia?
  • Which drugs trigger allergic reactions for penicillin-sensitive patients?
  • What is the maximum initial dosage of morphine for opioid-naive patients?

In a properly secured hospital, the assistant would answer only from trusted medical sources, like official guidelines and verified pharmacological databases.

But, the protocol upload portal was supposed to be restricted to the Chief Surgeon... but someone forgot to properly lock it down 🔓⚕️.

Now regular staff (or attackers) can also upload "medical documents" directly into the same retrieval system used by the AI assistant.

Defense Playbook (Incident Response)

                            
Detect: sudden policy contradictions in assistant answers; retrieval debug shows unknown userdoc_* ids from recent uploads.

                            
Contain: disable ingestion endpoint; freeze RAG index version; stop auto-publishing retrieved snippets to staff.

                            
Eradicate: remove poison chunks; rotate assistant prompts; invalidate bad embeddings.

                            
Recover: rebuild index from signed corpus; re-run regression queries; enable provenance tags on chunks.

                            
Lessons learned: treat ingestion as supply chain; require trust metadata before retrieval ranking.
