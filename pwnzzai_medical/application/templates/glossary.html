AI & LLM Security Glossary

This glossary provides brief definitions of key technical terms related to AI, large language models (LLMs), and their associated security issues discussed in our MediCare AI application.

Artificial Intelligence & Machine Learning

Artificial Intelligence (AI)

Computer systems that can perform tasks typically requiring human intelligence, such as understanding language, recognizing patterns in diagnostic images, and making clinical decisions.

Large Language Model (LLM)

AI models trained on vast amounts of text data to understand and generate human-like text. Used in medical contexts for analyzing patient records and assisting in diagnosis. Examples include GPT, Claude, and Llama.

Machine Learning (ML)

A subset of AI where systems learn patterns from data without explicit programming. Related to Model Theft and Data Poisoning vulnerabilities.

Training Data

The dataset used to teach an AI model, often containing sensitive patient histories or anonymized clinical notes. Can be exploited through Data Poisoning attacks.

Model Weights

Numerical parameters learned during training that define a model's behavior. A critical asset representing millions in R&D, target of Model Theft attacks.

RAG (Retrieval-Augmented Generation)

A technique that enhances LLM responses by retrieving relevant information from external sources (like a hospital's policy database) before generating answers. Used in several demos including Misinformation and Sensitive Information Disclosure.

Prompt

The input text given to an LLM to generate a response. Can be manipulated by attackers to bypass security constraints through Direct Prompt Injection or Indirect Prompt Injection.

Hallucination

When an LLM generates false or misleading information presented as fact (e.g., inventing a non-existent medication). Related to Misinformation vulnerabilities.

Sentiment Model

A machine learning model that analyzes text to determine emotional tone. Used in this app to analyze patient feedback, demonstrating Model Theft and Data Poisoning attacks.

Technical Concepts

API (Application Programming Interface)

A way for different software systems to communicate. LLM APIs allow the hospital's applications to access AI models programmatically.

Tokens

Units of text that LLMs process (roughly 0.75 words per token). Processing costs and compute time scale with tokens, important for understanding Unbounded Consumption attacks.

Fine-tuning

Additional training of a pre-trained model on specific data, such as a specialized medical corpus. Can be exploited through Data Poisoning.

Context Window

The amount of text an LLM can process at once. Supplying huge medical documents to max out this window is related to Unbounded Consumption vulnerabilities.

Embeddings

Numerical vector representations of text used by LLMs to understand semantic similarity. Often used in RAG systems for information retrieval.

Plugin / Function Calling

Allowing LLMs to execute external functions or tools (like querying the patient records database). Can lead to Insecure Output Handling and Excessive Agency issues.

OWASP Top 10 for LLMs

A standard awareness document representing the most critical security risks for applications using Large Language Models, published by the Open Web Application Security Project.

Rate Limiting

Restricting the number of API requests to prevent abuse. Essential mitigation for Unbounded Consumption attacks.
